5. **得点へ直接つながる処理**: 1〜4をhandlerに対応付ける

## 結論
compactの後に読むのは良い方向です。ただ、見取り図だけでは足りないと思います。compactで一番失いやすいのは、見取り図の中身ではなく`/main`の手順です。

## 理由
- **`AGENTS.md`は、compactの後も自動で読み直されます。** `.claude/rules/`のsymlink経由で、Claude Codeが毎回読み込むからです。
- **`/main`で読み込んだ手順書（`main.md`）は、会話の中にあるだけです。** compactで要約に置き換わり、細かい決まりが落ちやすくなります。たとえば「1回で決める」「分析の1文目は最大の制約」「holdの使い方」などです。
- **見取り図は、ほぼ動かない仕様です。** 要点・得点・FAILは、要約にもある程度残ります。
- **いちばん失うと困るのは、直近の判断のつながりです。** どの制約を追っていて、何を不採用にしたか。これはisuscopeの分析とキューに残っています。

## おすすめ
SessionStart hook（matcherが`compact`）で、役割ごとに「読み直すもの」を短く出します。中身は貼らず、場所だけ指します。
- **main**
  1. `.claude/commands/main.md`（手順）
  2. `isuscope list`と、直近数runの`analyze`（判断のつながり）
  3. `python3 scripts/proposal.py list`（キュー）
  4. 見取り図の要点・FAIL・「得点行動の入口」
- **improve**
  1. `.claude/commands/improve.md`
  2. 最新の`main analyzed`
  3. 見取り図
- 役割は、`.local/main-session.json`とworktreeの名前で見分けられます。

あわせて、`bench-hook.py`の毎回の「見取り図を読み返す」は外します。
