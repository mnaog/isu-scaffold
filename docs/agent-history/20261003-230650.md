**二つ、単純削除ではなく依存を切る必要があります。**

- **scoutの会話入力**  
  現在は登録されたoperatorセッションを読みます。これは「参照する会話セッションの明示指定」に変更します。2セッション常設という前提とworker進捗の入力は外します。scout自体は今回の廃止対象に含めなくてよいです。
- **配布漏れの検査**  
  `scripts/check-deployment.py`がworkerの受け渡し記録に依存しています。受け渡しDBへの依存は消しますが、必要なファイル・migrationが配布設定に含まれるかの検査は、役割に依存しない形で残します。

逆に、以下は残します。

- コードの先行回収、初期状態のcommit、非同期build、環境準備の自動化
- `.local/operation.lock`による変更操作の排他
- ローカルを正とする管理、deploy・rollback・配布検査
- baselineの保護とisuscopeの計測・採否記録
- worktreeごとのローカルDB・port・network分離
- 過去の会話・ベンチ・比較記録

過去の記録にある役割名は書き換えません。既存SQLiteの履歴や作業中のworktreeも、機能廃止に伴って自動削除する必要はありません。また、nginxの`worker_processes`や、運営向け出力を除外する`operator_line_pattern`は別の意味なので対象外です。

新しい運用ルールは、これくらいで足ります。
