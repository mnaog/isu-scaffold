# Phase 4: 最終構成を固定する

## 目的

終了前に新しい大規模変更を止め、最も良かった構成を確実に再現できる状態へ固定する。

最終計測と競技終了後の追試で、環境検査、再起動、initialize、スコア再現、データ永続化などを原因とする失敗が起きないことを確認する。

## 基本方針

- 新しい大規模な改善を行わない
- 最も高いスコアではなく、正しく再現できる最良の構成を採用する
- 修正は失格や障害を防ぐための小さく確実なものに限定する
- サーバー上の状態とローカルリポジトリを一致させる
- 最終構成をコミットしてGitHubへpushする
- 公式の終了手順と提出条件を優先する

## 公式の検査条件を確認する

当日の公式文書から、最終スコアと追試の条件を確認する。確認した原文は`docs/official/`に保存する。

- 最終スコアとして採用されるベンチマーク
- 再起動後に必要なスコア再現率
- envcheckなどの競技環境検査
- ポータルに登録されているサーバーと負荷走行対象
- サーバー台数、VPC、インスタンスタイプなどの制約
- 保護されているservice、管理ユーザー、SSH設定
- initialize、整合性チェック、負荷走行、最終チェックの内容とタイムアウト
- 再起動後に確認される永続データ
- フロントエンドの表示確認
- 競技終了後に禁止される操作

過去の大会と同じ条件だと決めつけず、当日の公式情報を正とする。

## 最終構成を選ぶ

- isuscopeの履歴から、採用するrunとGitコミットを決める
- スコア、エラー、失敗率、再現性を確認する
- 未採用の実験や一時的な設定を取り除く
- 全サーバーが採用したコードと設定になっていることを確認する
- 未コミット変更を残さない

## 計測によるオーバーヘッドを外す

最終スコアに不要な計測やデバッグ機能を停止する。

- profilerや一時的なcollector
- デバッグログ
- MySQLの重いクエリログ
- 一時的なトレース
- 調査用プロセス

停止後も、障害調査に最低限必要なログは残す。計測を外した構成でもベンチマークを実行し、挙動が変わっていないことを確認する。

## 再現性を確認する

- クリーンなローカル状態から最終デプロイを実行する
- 設定ファイルを検証する
- 全サービスを再起動する
- 公式の追試と同じ単位で全サーバーをOS再起動する
- 再起動後に必要なサービスが自動起動することを確認する
- サーバーの再起動順に依存せず起動できることを確認する
- envcheckなど、公式の競技環境検査を全サーバーで実行する
- initializeが正常に完了することを確認する
- 再起動後も複数台の役割とデータ配置が維持されることを確認する
- 初期データやキャッシュが正しく再構築されることを確認する

サーバー上だけに存在する手作業の変更を残さない。

## 最終ベンチを実行する

- 計測を外した採点用構成でベンチマークを実行する
- 専用の最終計測コマンドは使わず、採点用構成で通常の`isuscope run`を実行する
- `isuscope brief latest`と採用候補を指定した`isuscope query latest --base BASE_RUN ...`で全体および主要得点経路を比較し、最終runをrun ID指定で分析する
- 可能であれば複数回実行し、スコアの振れ幅を見る
- 整合性エラー、失格条件、タイムアウトを確認する
- シナリオ別の成功数と得点を確認する
- CPU、メモリ、ディスク、ログ容量に余裕があることを確認する
- ベンチ終了後もサービスが正常であることを確認する

不安定な最高スコアより、安定して再現できる構成を優先する。

## 追試を再現する

当日の公式手順を優先し、可能な範囲で主催者の追試を自分でも再現する。

```text
全サーバーが起動していることを確認する
→ ポータルのサーバーとAWS上のサーバーを照合する
→ 全サーバーを再起動する
→ 競技環境検査とサービス起動を確認する
→ 採点対象へベンチマークを実行する
→ 最終スコアに対する再現率を確認する
→ ベンチ中に作成・更新されたデータを特定する
→ 全サーバーをもう一度再起動する
→ 対象データが再起動後も取得できることを確認する
→ ブラウザでフロントエンドを確認する
```

直近の大会では、再起動後のベンチがFAILすること、一定のスコア再現率を下回ること、環境検査に失敗すること、データが永続化されていないこと、フロントエンドが正しく表示されないことなどが失格条件に含まれている。

メモリだけに保持しているデータやwrite-behind中のデータが、追試前の再起動で失われないことを特に確認する。

## 終了前の確認

- 最終構成がコミットされている
- private GitHubリポジトリへpushされている
- デプロイ対象のコミットが明確になっている
- `git status`がcleanになっている
- 公式の提出、再起動、終了手順を確認している
- ポータル上の全サーバーが同一の正しい環境に所属している
- ポータル上の全サーバーが起動している
- 追試に必要な管理用service、ユーザー、鍵、ポートを壊していない
- 採点対象のサーバーが正しく選択されている
- 必要なサービスが自動起動する
- 不要なベンチやデプロイを実行していない
- 競技終了後は公式アナウンスまでサーバーへ接続・操作しない
- 公式アナウンスまでAWS環境を停止または削除しない

終了直前は、明確な不具合の修正以外で構成を変更しない。

## 完了条件

- 最終構成をローカルから再デプロイできる
- 全サーバーのOS再起動後も正常に動作する
- 公式の競技環境検査に成功する
- initializeとベンチマークが正常に完了する
- 公式基準を満たすスコアを再現できる
- ベンチ中に書き込まれたデータが再起動後も取得できる
- フロントエンドが正しく表示される
- 最終構成のGitコミットとisuscope runを特定できる
- 公式の提出と終了手順が完了している
