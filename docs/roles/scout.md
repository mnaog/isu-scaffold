# scout

役割はscout。現状を把握して自由に探索し、見落とし・疑問・仮説を最大300文字で報告する。4体の指示と入力形式は同じで、探索角度や専門分野は割り当てない。「発見なし」「順調そう」も最新報告として保存する。
共通指示は[scout-prompt.txt](scout-prompt.txt)。読み取り専用はプロンプトで指示する。CLI権限制御は必須条件ではなく、OSレベルで保証するものではない。

## 起動と停止

Python 3.9以上とSQLite（Python標準ライブラリ）を使用する。scaffoldはmain worktreeのrootから操作する。

```bash
make operations-init
./scripts/scout conversation codex '<参照する実セッションID>'
./scripts/scout conversation claude '<参照する実セッションID>'
./scripts/scout check
./scripts/scout input   # LLMを呼ばず入力プレビューを生成
make board             # http://127.0.0.1:8765 。Ctrl-Cで画面のserverだけ停止
# 別ターミナルで、人間がPhase 2への移行を決めた後
make scout-start
make scout-status
make scout-stop
```

開始は明示コマンドだけ。Phaseを推測して自動起動しない。ボードに開始・停止スイッチはない。常駐処理は作業セッションの終了から独立して動く。各scoutは新しいCLIセッションで入力生成→探索→最新状況の再確認→報告保存を行い、Git用出力まで完了した時点から900秒後に次回実行する。4体の時刻は独立している。
停止時は待機と実行中CLIを終了する。再開時は保存済みの次回予定を尊重する。失敗時は900秒から最大3600秒まで間隔を延ばし、ボードにエラーを表示する。空回答・300字超過も失敗とし、最後の成功報告は残す。

同じscoutの手動実行と常駐実行にも共通のOSファイルlockを使う。これはローカル実行の多重起動防止のみであり、作業担当の調整や実験leaseではない。lockファイルは削除しない。

## 設定と接続確認

`config/operations.json`に呼び出しargv、model、出力形式、時間、シナリオ参照先、比較元runを置く。端末固有の上書きはファイル全体を`.local/operations.json`へコピーする。秘密をGit管理設定に入れない。設定変更は常駐処理を停止してから行い、再起動する。

argvはshell文字列でなく配列。`{model}`、`{session}`（各回のUUID）、`{output}`（最終回答ファイル）を置換し、共通プロンプトはstdinに渡す。resume/continue指定は使わない。adapterは`file`、`claude-json`、`codex-json`、`opencode-json`、`text`を持つ。別CLIがstdin非対応なら、stdinを読み取ってそのCLIへ渡す小さなadapterを設定する。

未導入CLI・認証不足・model ID未確認は利用不可として表示し、代替モデルへ切り替えない。Kimi Code/Kimi K3は実機確認後に`unavailable`を除き、正確なargv/modelを設定する。OpenCodeはLithos無印の`lithosai/deepseek-ai/DeepSeek-V4.1-Flash`を設定済みで、[Lithos接続手順](opencode-lithos.md)に従って接続する。Kimiは任意で、利用可能なら動かし、未導入・未設定なら利用不可のまま他を動かす。採用・除外の判断待ちやPhase 0の完了待ちは設けない。未利用のscoutがあっても他は動く。

```bash
./scripts/scout once claude --smoke
./scripts/scout once codex --smoke
./scripts/scout once kimi --smoke
./scripts/scout once opencode --smoke
```

smokeは共通指示に接続確認指示を加えて各CLIを新規起動する。探索や運用報告の投稿はせず、ローカルに応答と実行ログを保存する。通常の単発運用は`./scripts/scout once <name>`。

Codexの非対話実行は[公式ドキュメント](https://developers.openai.com/codex/noninteractive/)と実機`codex exec --help`を確認している。接続検証の結果と未確認事項は[実機検証](connection-check.md)に記録する。

## 入力と保存先

- シナリオ: Phase 1の`docs/benchmark-scenario.md`。公式ルールとAGENTS.mdの指示に従う資料だけで整理する。
- 計測: `isuscope list`の最新の終了run（失敗・中断も明示）、`brief --limit 5`、HTTP・SQL load・ホストload・benchmarkの`query --limit 8`。比較元は設定の`base_run`を明示使用し、未指定なら比較なし。採用runを推測しない。
- 会話: 明示指定した会話セッションだけ（利用するagent分のみ指定）。各直近6000文字、元ファイルとIDを添える。
- 根拠: run ID、比較元ID、runのcommit/dirty、現在のcommit/dirty、取得時刻、実行した取得コマンド、資料のパス。

入力生成はLLMを使わない。`isuscope`未設定・計測欠落はエラー情報として渡す。ボードのスコア履歴は同じ取得処理を使い、人間向けのHTTP/SQL詳細は別の読み取り専用APIで必要時に取得する。scout入力の件数は増やさない。計測処理やrunの採否変更は実装しない。画面は5秒、計測は30秒ごとに更新する。終了前のrunも実行状況用に保持するが、スコア推移と比較には終了runだけを使う。スコア推移は直近100件のrunのうち終了したrunを開始時刻順で表示する。PASSは折れ線、FAIL・中断は×印、スコア欠落は未取得欄に表示し、点にカーソルを合わせるかフォーカスすると時刻・run ID・commit・試したことを確認できる。

### ボードでの比較・詳細閲覧

通常は最新の終了runを自動表示する。グラフの上の「表示する計測結果」で日時・スコアから結果を選ぶ。「前の結果」「次の結果」で直近100件内の終了runを移動し、「最新に戻る」で自動表示に戻れる。結果の選択と移動は左側に常時表示し、比較元・サーバー・取得件数はその下の「比較・表示設定」に折り畳む。スコアの点のクリック／Enter／Spaceでも表示runを切り替える。「比較元」は「分析の比較元に追従」を既定にし、選択runの保存済み分析にある`base_run_id`を使う。未分析または比較元未記録なら比較なしとし、前回runや採用runを推測しない。画面で任意の比較元または「比較なし」へ変更でき、run移動後も手動選択を保つ。`config/operations.json`の`base_run`はscout入力用であり、画面の既定値とは独立する。選択はそのタブだけの閲覧状態で、設定やscout入力、採否は変えない。

スコア・HTTP・SQLを比較元／対象／差分／変化率で表示し、仮説・分析・変更の採否・計測commitも確認できる。試したこと（仮説）と分析状態を常時表示し、分析本文と採否は折り畳む。手動の比較元が保存済み分析の比較元と違う場合は、折り畳みの外で違いを明示する。採否は関連する変更の現在の判断で、当時の判断やdeploy済みを意味しない。HTTP・SQLの回数と平均時間は「比較元 → 対象」を同じ行に表示し、列見出しで対象の値をソートできる。片方だけにある行、欠測、比較元が0で変化率を算出できない値は0で補わない。

HTTPはrun全体、SQLは`--window load`のdigest単位。25／50／100件を取得し、列見出しのクリックで回数・合計・平均・p95・合計時間差分を並べ替える。ソートは取得済み行の範囲に限り、切り詰めは件数表示で知らせる。行を開くとHTTP status、SQLのロック時間・走査行数などを表示する。長いSQLはisuscope側の出力上限で省略される場合があり、digest IDとともに明示する。

詳細取得は最大2MB/コマンド、30秒のキャッシュ（最大8選択）を使う。再取得ボタンもキャッシュ有効期間内は同じスナップショットを返す。自動取得は約30秒ごと。scoutの軽量入力は従来の200KB/コマンドの上限を維持する。ユーザー遷移の毎run収集は追加しない。

DBはGit共通ディレクトリの親、すなわちmain worktreeの`.local/operations/state.sqlite3`。全worktreeが同じ場所を参照する（通常の非bareリポジトリが対象）。入力・CLI出力・詳細実行ログは`.local/operations/`に保存する。別worktreeの`.local/`へ複製しない。

最新成功報告4件を`docs/scout-board.md`へ自動上書き出力する。自動commitはしない。過去投稿・他scout報告は入力へ入れない。Gitファイルは報告だけを保存し、変化の多い実行状態はSQLiteに置く。画面はloopbackでGETのみを提供する。

会話の指定はagentごとに最新の明示登録で置き換わる。未指定のagentは入力へ含めない。旧役割の登録や履歴DBから会話を自動選択しない。

### ボードの負荷分析

選択runの`brief --limit 25`からホスト別CPU・コア・PSI・memory・service、upstream、クライアント接続、CPU上位関数、collectorの取得状況を表示する。HTTP/SQLと同じ画面で、`series --window load --bucket 5`による負荷走行の時系列とMySQLステータスを自動表示する。概要時系列は最大1000行、MySQLは指定9 metric・最大3000行。独立した読み取りは並列化し、既存の30秒キャッシュを使う。追加collectorやベンチは起動しない。

グラフの横軸は負荷走行開始からの秒数。要求数・SQL回数は毎秒レートではなく区間内の件数、HTTP p95は区間内の分位値の最大として表示する。欠測点は0で補わず、欠落区間を線で結ばない。load区間を取得できない場合はその欄へエラーを表示し、wholeへ自動で置き換えない。

「APIの流れと処理時間」は未計測時に実測と明確に区別したサンプル図と、計測後に表示する案内を出す。ユーザー遷移は固定の読み取り専用SQLで最初にPASSしたsurvey-runを探し、その`brief --limit 200`から最大80遷移をSVGの接続図で表示する。循環・自己ループを含め、接続関係で段を分ける。ノードには選択runのHTTP計測（最大500行）から、node別の回数・平均・p95・合計時間・エラーを重ねる。バーはAPIごとの最大サーバー合計時間を、図全体の最大値に対して表示する。ノードをクリックするとHTTP詳細を開ける。未取得は0扱いせず、図にないAPIは別表へ出す。初回の遷移回数は既定で表示し、線幅も回数に応じて変える（表示中の最大値を基準に1〜6px）。回数ラベルは設定で非表示にでき、通常runの遷移回数とは混同しない。図はオフラインで描画し、同じ接続のMermaidソースも保存できる。直近100件より古いsurveyも対象とし、参照runを明記する。通常runへの遷移収集追加や再ベンチは行わない。isuscopeの遷移解析は`msec - reqtime`で開始時刻を求める。`transition.*`の品質metric（最大1000行）で重複実行・同時刻・旧形式を判別し、順序が曖昧な矢印は破線にする。品質metricのない既存surveyはすべて破線とする。実線も観測順であり、因果順序とは扱わない。cache HIT/MISSは現行の標準計測にはないため、表示値を推定しない。


### 人間向けの分析画面

スコア推移、scoutの最新報告、run・分析、シナリオ、ホスト、時間軸、HTTP、SQL、MySQL、upstream、CPU、計測欠落、ベンチ走行履歴を一ページに表示する。scout報告は常時表示し、停止ラベルは表示しない。タブによる表示切り替えは行わない。ページ内リンクの見出し列も設けない。普段読むデータを主に置き、低頻度の操作は結果選択の下の「比較・表示設定」にまとめて折りたたむ。見出しは表示内容を具体的に表し、比較条件・集計範囲・欠測など解釈に必要な情報は残す。閾値による自動解釈や「次に確かめること」は表示しない。
取得コマンドと計測の元データは画面に表示せず、取得時にブラウザの開発者コンソールへ`console.debug`で出力する。

HTTP・SQLは合計時間順の表を基本とし、重複する並べ替えボタン列を置かない。列見出しで並べ替え、API・SQL名から詳細を開く。HTTPのエラー数、SQLのロック時間・走査行数/回は常時表示する。API図は曲線と余白で流れを示し、未計測の表示例は大きく明示する。拡大率・遷移回数・保存は図の表示設定にまとめる。

対象run・比較元・node・取得件数を共通の表示条件とする。node指定は取得済みのHTTP/SQL・ホスト・時系列・CPU等を絞り込む。スコア・採否・計測欠落はrun全体のまま。サーバー側の取得上限を超えた行は検索・ソート対象にならない。

時間軸のサーバー凡例は各図の右上に置く。時間軸はカーソルまたは左右矢印で同じ経過秒を照合する。表示bucketの半幅より離れた値・欠測値は未取得とする。時間範囲での再集計は行わない。ベンチ走行履歴には仮説と分析状態を表示し、終了runを選択して詳細を確認する。シナリオ群別のセッション集計、cache HIT/MISS、詳細flamegraphは今回追加していない。

HTTP・SQLの合計時間と差分を視覚的に強調する。差分の色は増減のみを表し、改善・悪化を自動判定しない。未取得グラフはコンパクトに表示し、取得値のあるグラフの面積を確保する。

### 投稿前の最新確認

scoutは最終回答の直前に`./scripts/scout current`を実行する。このコマンドは最新の終了runと`brief --limit 5`、現在のcommit・working tree・diff統計、明示登録した会話の末尾を標準出力へ返す。DB初期化・入力ファイル保存・他scout報告の取得は行わない。探索中に状況が変わった場合は同じセッション内で指摘に関係する根拠を再確認し、解消済みの指摘を取り下げる。再確認に失敗したら報告本文に明示する。CLIの再起動や探索全体のやり直しは増やさない。

これはscoutへの実行指示であり、投稿時点との完全な同時性を保証する仕組みではない。900秒の定期実行は維持する。画面のscoutカードには参照runや選択runとの差分を追加しない。

### 実行状況

画面上部には、選択runとは独立した現在の共有操作、直近の終了ベンチの分析状態、deployの最終記録と最後に成功したdeployのcommitを小さく表示する。`.local/operation.lock/lock`が実際に保持されていることを非ブロッキングで確認し、`owner`に記録された操作と開始時刻を表示する。ownerファイルだけでは実行中と判定しない。lockファイルは作成・削除しない。

deployの段階と時刻は`.local/deploy-transactions/`、最後に成功したdeployは`.local/current-deploy-commit`から読む。記録は実環境との一致確認を意味しない。未終了runが残っていても、対応するベンチの共有操作を確認できないときは実行継続未確認と表示する。実行記録は5秒、ベンチ情報は30秒更新で、AIの思考中・実装中・残り時間は推測しない。
